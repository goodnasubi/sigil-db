# Sigil DB 保存形式 v1 仕様書

本仕様書は、ADR 0045（決定 1・決定 2）に準拠した Sigil DB 保存形式 v1 のバイナリレイアウトおよび上限値を規定する。

## 1. 共通 96 バイトヘッダ構造

すべてのファイル・ページ・WAL レコードの先頭 96 バイトは共通の固定長ヘッダ構造を持つ。

| オフセット | サイズ | 型 | フィールド | 説明 |
|---|---|---|---|---|
| `0..8` | 8B | `[u8; 8]` | `magic` | 識別マジックバイト（`SIGILDB1` / `SIGILPG1` / `SIGILWL1`） |
| `8..12` | 4B | `u32 LE` | `version` | 形式版（v1 = `1`） |
| `12..14` | 2B | `u16 LE` | `byte_order` | バイト順（`1` = リトルエンディアン固定） |
| `14..16` | 2B | `u16 LE` | `kind` | ページ種別またはレコード種別 |
| `16..20` | 4B | `u32 LE` | `length` | 全長（ページは `8192`、WAL レコードは実長） |
| `20..24` | 4B | `u32 LE` | `reserved` | 予約領域（ゼロ埋め） |
| `24..40` | 16B | `[u8; 16]` | `db_id` | データベース一意識別子 (UUID / 16B) |
| `40..48` | 8B | `u64 LE` | `generation` | 世代番号（フォーマット・バックアップ世代） |
| `48..56` | 8B | `u64 LE` | `page_no_or_lsn`| ページ番号（0..2^24-1）または LSN（WAL） |
| `56..60` | 4B | `u32 LE` | `item_count_or_tx_id` | ページ内アイテム数、または WAL トランザクション ID |
| `60..64` | 4B | `u32 LE` | `content_offset` | 空き領域境界オフセット、または WAL 対象ページ番号 |
| `64..96` | 32B | `[u8; 32]` | `checksum` | SHA-256 検査値（オフセット 64..96 を 0 埋めして計算） |

### 1.1 マジックバイト
- DB メタページ・DB ファイルヘッダ: `SIGILDB1` (`[83, 73, 71, 73, 76, 68, 66, 49]`)
- ページヘッダ: `SIGILPG1` (`[83, 73, 71, 73, 76, 80, 71, 49]`)
- WAL レコードヘッダ: `SIGILWL1` (`[83, 73, 71, 73, 76, 87, 76, 49]`)

### 1.2 検査値 (SHA-256)
- 検査値計算時は、バイト列のオフセット 64..96（32 バイト）を 0 に設定した上で SHA-256 を計算する。
- 検証時は、計算された SHA-256 と格納されている検査値を定数時間比較（`ct_eq`）で検証する。

## 2. ページ構造 (8192 バイト固定長スロットページ)

各ページは固定 8192 バイトで構成され、スロット配列方式を採用する。

```
+-------------------------------------------------------------------+
| 固定 96B ヘッダ                                                   |
+-------------------------------------------------------------------+
| スロット配列: (offset: u16, len: u16) * item_count               |
|   -> 順次下位から上位へ伸長                                       |
+-------------------------------------------------------------------+
| 空き領域 (Free Space)                                             |
|   (slots_end .. content_offset)                                   |
+-------------------------------------------------------------------+
| アイテムデータ領域 (Rows / Keys)                                  |
|   <- 順次上位から下位へ配置 (content_offset が下がる)             |
+-------------------------------------------------------------------+
```

- **スロットエントリ**: 4 バイト (`offset: u16 LE`, `len: u16 LE`)
- **空き容量計算**: `content_offset - (96 + item_count * 4)`。各アイテムの挿入には 4 バイトのスロットエントリも必要となるため、挿入可能な最大アイテムサイズは `空き容量 - 4` バイト。
- **境界検査**: `new_slots_end > new_content_offset` の場合は `DbError.Limit` で挿入を拒否する。

## 3. WAL レコード構造

すべての WAL レコードは共通の固定 96 バイトヘッダ（マジック `SIGILWL1`）で始まり、種別ごとのペイロードを持つ。

- **レコード種別 (`kind`) とペイロード長**:
  - `1`: Begin（トランザクション開始）
    - ペイロード: なし（全長 96 バイト）
  - `2`: Redo（ページ全更新イメージ）
    - ペイロード: 8192 バイトの全ページ像（全長 8288 バイト）
    - ヘッダの `content_offset` に対象 `page_no` を格納
  - `3`: Commit（コミット記録、ADR 0045 決定 3 準拠）
    - ペイロード: 48 バイト（全長 144 バイト）
      - `first_lsn` (8B `u64 LE`): トランザクション先頭 LSN（Begin レコードの LSN）
      - `last_lsn` (8B `u64 LE`): コミット LSN（Commit レコード自身の LSN と一致）
      - `bundle_checksum` (32B `[u8; 32]`): トランザクション先行レコード列（Begin および全 Redo）を束ねる検査値
    - ヘッダの `content_offset` に `record_count`（Begin、全 Redo、および Commit 自身を含む総レコード数、最小 2）を格納
    - 整合性条件: `last_lsn - first_lsn == record_count - 1`（整数溢れを回避するため減算形式で検査）
  - `4`: Abort（ロールバック記録）
    - ペイロード: なし（全長 96 バイト）
  - `5`: Checkpoint（チェックポイント記録）
    - ペイロード: 8 バイト（全長 104 バイト）
      - `checkpointed_lsn` (8B `u64 LE`): チェックポイント確定 LSN

### 3.1 トランザクション束ねる検査値 (`bundle_checksum`) の計算規則 (ADR 0045 決定 3)
コミット時に不完全なトランザクションやレコード抜け・改ざんを確実に検出し、完全な commit で閉じた tx のみを redo 復旧の対象とするため、以下の計算規則を規定する。

1. **対象レコード**: 当該トランザクションに属する Begin レコードから Commit レコード直前までの全レコード（Begin およびすべての Redo レコード、計 `record_count - 1` 件、最小 1 件）。
2. **順序**: LSN 昇順（`first_lsn` から `last_lsn - 1`）。
3. **入力データ列**: 各先行レコードの完全なバイナリ表現（各レコードの 96B ヘッダおよびペイロード、各レコード固有の SHA-256 検査値を含むバイナリ）を、LSN 昇順でそのまま連結したバイト列。
4. **ハッシュ計算**: 連結バイト列の SHA-256（32 バイト）。
5. **照合**: 復旧時・検証時に、先行レコード列から `compute_tx_bundle_checksum` で再計算し、Commit レコードに記録された `bundle_checksum` と定数時間比較（`ct_eq`）で照合する（不一致時は `DbError.Corrupt`）。
6. **復旧段での完全検証**: 本段（P4-1 形式核）の `verify_tx_bundle_checksum` は検査値の照合を行う。先行レコード列の件数が `record_count - 1` と一致すること、先頭が Begin で LSN が `first_lsn` であること、LSN が連続していること、各レコードの `tx_id`・`db_id`・世代が Commit と一致すること等の統合検証は、後続の WAL／復旧段で完全な commit 判定関数としてまとめる。

## 4. 値・キー・行の符号化形式

### 4.1 値の型タグと表現
- `1`: `Int` (64bit LE 符号付き整数, 8 バイト)
- `2`: `Bool` (0 = false, 1 = true, 1 バイト)
- `3`: `Str` (u32 LE 長さ + UTF-8 バイト列)
- `4`: `Bytes` (u32 LE 長さ + バイト列)

### 4.2 大小順序規則 (ADR 0045)
- 異なる型の比較: 型不一致として拒否する（`DbError.TypeMismatch`）。異なる型間の順序は定義しない（ADR 0045 決定 2）。
- 同一型同士の順序:
  - `Int`: 数値の昇順比較
  - `Bool`: false (0) < true (1)
  - `Str`: バイト列の辞書順比較
  - `Bytes`: バイト列の辞書順比較

### 4.3 キーおよび行の符号化
- **Key**: 値の列を順次符号化。最大符号化サイズは 1024 バイト (`max_key_encoded_size`)。
- **Row**: `u16 LE` 列数（最大 64） + 各列の値符号化列。最大符号化サイズは 4096 バイト (`max_row_encoded_size`)。

## 5. システム上限値一覧 (ADR 0045 決定 2)

| 項目 | 上限値 | 超過時の扱い |
|---|---|---|
| 最大ページ番号 | `16,777,216` (2^24 ページ = 128 GiB) | `DbError.Limit` で拒否 |
| テーブル数 / 索引数 | 各 `1,024` | `DbError.Limit` で拒否 |
| 列数 | `64` 列 | `DbError.Limit` で拒否 |
| 1 行最大サイズ | `4,096` バイト | `DbError.Limit` で拒否 |
| 1 キー最大サイズ | `1,024` バイト | `DbError.Limit` で拒否 |
| トランザクション更新ページ数 | `4,096` ページ (32 MiB) | `DbError.Limit` で拒否 |
| 1 トランザクション WAL 容量 | `67,108,864` バイト (64 MiB) | `DbError.Limit` で拒否 |
| WAL 総容量 | `67,108,864` バイト (64 MiB) | `DbError.Limit` で拒否 |
| 作業用メモリ上限 | `268,435,456` バイト (256 MiB) | `DbError.Limit` で拒否 |
| ページサイズ | `8,192` バイト固定 | 違反時は `DbError.Corrupt` |
| ヘッダサイズ | `96` バイト固定 | 違反時は `DbError.Corrupt` |

## 6. チェックポイントと復旧プロトコル (ADR 0045 決定 3)

### 6.1 ディレクトリ構成とロック
- データベースは 1 つのディレクトリ内に以下のファイル群を配置する。
  - `sigil_db.lock`: 排他制御用ロックファイル（起動時に `try_lock_exclusive` で排他ロックを取得、取得失敗時は `DbError.Busy`）
  - `main.db`: ページ本体ファイル（先頭は meta ページ、以降各ページが 8192 バイト境界で配置）
  - `wal.log`: 先行書き込みログ（WAL レコード列）
  - `checkpoint.meta`: チェックポイント確定情報（96 バイト固定ヘッダ）
  - `checkpoint.meta.tmp`: チェックポイント更新用の一時ファイル

### 6.2 チェックポイントの 5 手順 (ADR 0045 決定 3)
1. **WAL 先行同期**: 対象 commit までの WAL (`wal.log`) を `sync_all` する。
2. **ダーティページの本体反映と同期**: コミット済み更新ページ群を `main.db` の該当オフセットへ書き込み、`main.db` を `sync_all` する。
3. **チェックポイントメタデータ一時ファイルの作成と同期**: `checkpoint.meta.tmp` に新しい確定 LSN を含む 96B ヘッダ（マジック `SIGILDB1`, kind=5）を書き込み `sync_all` する。
4. **原子的置換と親ディレクトリ同期**: 同一 FS の `rename` で `checkpoint.meta` に原子的置換し、親ディレクトリを `sync` する。
5. **古い WAL の回収と親ディレクトリ同期**: `wal.log` を切り詰めて回収（truncate）し、その `sync_all` と親ディレクトリの `sync` を行う。

### 6.3 復旧（リカバリ）の規則
- **完全コミットの判定**: WAL レコード列を走査し、Begin + 全 Redo + Commit（`record_count`、LSN 連続性、`tx_id`、`db_id`、世代、`bundle_checksum`）が完全に揃っているトランザクションのみを Redo 復旧の対象とする。
- **未完末尾の破棄**: クラッシュ時に発生した最後の有効な commit より後ろの不完全な未完末尾（コミットされていない Begin や途中までの Redo、途切れたレコード）は安全に破棄（切り詰め）する。
- **中間破損の拒否**: 壊れた領域より後ろに有効なレコードが続く場合（中間破損）、または `db_id`・世代不一致、`checkpoint.meta` の破損を検出した場合は、暗黙復旧せず直ちに `DbError.Corrupt` で起動を拒否する。
- **CommitUnknown**: WAL 追記・同期失敗時、成否不明として `DbError.CommitUnknown` を返し、以降のデータベースハンドルを無効化（ポイズン）する。

## 7. データベース核の第 3 段: メタページ・B+tree・カタログ (ADR 0045 決定 2)

### 7.1 メタページ (page 0) の payload

共通ヘッダ（96 バイト）の直後に 32 バイトの payload を置く（すべて u32 LE）。`rel_version = 0` は第 2 段までの空のメタページで、全 payload が 0 であることを検査し、既定値（`page_count = 1`）として扱う。

| オフセット | 内容 |
|---|---|
| 0 | `rel_version`（0 = 未初期化、1 = 関係層あり。他は `UnsupportedFormat`） |
| 4 | `catalog_root`（カタログ B+tree の根ページ番号、0 = まだ無い） |
| 8 | `page_count`（次に割り当てるページ番号。`1..=2^24`） |
| 12 | `free_head`（空きページ連鎖の先頭、0 = 無し） |
| 16 | `free_count`（空きページ数。`free_head` と 0 かどうかが一致すること） |
| 20 | `table_count`（≤ 1024） |
| 24 | `index_count`（≤ 1024） |
| 28 | 予約（0） |

### 7.2 B+tree／空きページのレイアウト

B+tree の葉・内部ページと空きページは 2 章のスロットページ構造を使い、アイテム 0 をページ末尾、アイテム n-1 を `content_offset` に置く。復号時に、隙間・重なり・順序違反がない（アイテムが末尾から詰まっている）ことを厳密に検査する。

- 葉のアイテム: `[key_len u16 LE][key][value]`。キーの昇順に並ぶ。
- 内部ページのアイテム: `[key_len u16 LE][key][child u32 LE]`。アイテム 0 のキーは空（-∞）。子ページのキー範囲は次のアイテムのキーで区切る。
- 根ページ番号は固定（根の分割・縮約でも根のページ番号は変わらない）。
- キーは値の符号化（4.1）の連結で、バイト列ではなく「復号した値の列」として比較する。短い接頭辞が先に来る。範囲走査の境界は接頭辞比較で、両端を含む。
- 空きページ（kind = free）は 1 つの 4 バイトアイテム（次の空きページ番号 u32 LE、0 = 終端）を持つ。

### 7.3 表・索引・カタログ

- 表の B+tree: キー = 主キー（単一列）の符号化、値 = 行の符号化。
- 二次索引の B+tree: キー = 索引値の符号化 + 主キーの符号化、値 = 空。非一意索引は同値を主キー順に並べる。一意索引は挿入前に索引値だけの存在検査を行い、重複は `UniqueViolation`。
- カタログ B+tree（根は `catalog_root`）:
  - キー `[Int 1, Str 表名]` → 行 `[Int 根, Int 主キー列, Bytes 列定義, Bytes 索引定義]`。列定義は `(Str 列名, Int 型タグ)` の符号化の連結、索引定義は `(Str 索引名, Int 列, Bool 一意, Int 根)` の符号化の連結。
  - キー `[Int 2, Str 索引名]` → 行 `[Str 表名]`（索引名は DB 全体で一意）。
- 名前は 1〜32 バイトで制御文字を含まない。表の定義が 1 行（4096 バイト）に収まらなければ `Limit`。
- カタログ・表・全索引・ページの割当て／解放・メタページの件数は同一 tx で更新される。

### 7.4 エラーと tx

関係 API が Err を返すと tx は中止状態になり、以後の操作と `tx_commit` は `TxAborted`、`tx_rollback` のみ成功する。変更は作業用領域にあるだけで WAL にもページにも書かれないので、rollback で部分変更は残らない。`Limit`（commit 時の WAL 総量・tx WAL・作業メモリを含む）も同様に tx を中止し、部分 commit を残さない。重複主キー・一意違反・型不一致は書込みの前に検査する。

### 7.5 今回の範囲外（未対応）

バックアップ／互換性（第 4 段）、検証記録（第 5 段）、圧縮、SHA-1。NULL・浮動小数・照合順序・外部キー・式索引は持たない。
