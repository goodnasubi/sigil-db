# Sigil DB 保存形式 v1 仕様書

本仕様書は、ADR 0045（決定 1・決定 2）に準拠した Sigil DB 保存形式 v1 のバイナリレイアウトおよび上限値を規定する。

## 1. 共通 96 バイトヘッダ構造

すべてのファイル・ページ・WAL レコードの先頭 96 バイトは共通の固定長ヘッダ構造を持つ。

| オフセット | サイズ | 型 | フィールド | 説明 |
|---|---|---|---|---|
| `0..8` | 8B | `[u8; 8]` | `magic` | 識別マジックバイト（`SIGILDB1` / `SIGILPG1` / `SIGILWL1`） |
| `8..12` | 4B | `u32 LE` | `version` | 形式版（v1 = `1`） |
| `12..14` | 2B | `u16 LE` | `byte_order` | バイト順（`1` = リトルエンディアン固定） |
| `14..16` | 2B | `u16 LE` | `kind` | ページ種別またはレコード種別 |
| `16..20` | 4B | `u32 LE` | `length` | 全長（ページは `8192`、WAL レコードは実長） |
| `20..24` | 4B | `u32 LE` | `reserved` | 予約領域（ゼロ埋め） |
| `24..40` | 16B | `[u8; 16]` | `db_id` | データベース一意識別子 (UUID / 16B) |
| `40..48` | 8B | `u64 LE` | `generation` | 世代番号（フォーマット・バックアップ世代） |
| `48..56` | 8B | `u64 LE` | `page_no_or_lsn`| ページ番号（0..2^24-1）または LSN（WAL） |
| `56..60` | 4B | `u32 LE` | `item_count_or_tx_id` | ページ内アイテム数、または WAL トランザクション ID |
| `60..64` | 4B | `u32 LE` | `content_offset` | 空き領域境界オフセット、または WAL 対象ページ番号 |
| `64..96` | 32B | `[u8; 32]` | `checksum` | SHA-256 検査値（オフセット 64..96 を 0 埋めして計算） |

### 1.1 マジックバイト
- DB メタページ・DB ファイルヘッダ: `SIGILDB1` (`[83, 73, 71, 73, 76, 68, 66, 49]`)
- ページヘッダ: `SIGILPG1` (`[83, 73, 71, 73, 76, 80, 71, 49]`)
- WAL レコードヘッダ: `SIGILWL1` (`[83, 73, 71, 73, 76, 87, 76, 49]`)

### 1.2 検査値 (SHA-256)
- 検査値計算時は、バイト列のオフセット 64..96（32 バイト）を 0 に設定した上で SHA-256 を計算する。
- 検証時は、計算された SHA-256 と格納されている検査値を定数時間比較（`ct_eq`）で検証する。

## 2. ページ構造 (8192 バイト固定長スロットページ)

各ページは固定 8192 バイトで構成され、スロット配列方式を採用する。

```
+-------------------------------------------------------------------+
| 固定 96B ヘッダ                                                   |
+-------------------------------------------------------------------+
| スロット配列: (offset: u16, len: u16) * item_count               |
|   -> 順次下位から上位へ伸長                                       |
+-------------------------------------------------------------------+
| 空き領域 (Free Space)                                             |
|   (slots_end .. content_offset)                                   |
+-------------------------------------------------------------------+
| アイテムデータ領域 (Rows / Keys)                                  |
|   <- 順次上位から下位へ配置 (content_offset が下がる)             |
+-------------------------------------------------------------------+
```

- **スロットエントリ**: 4 バイト (`offset: u16 LE`, `len: u16 LE`)
- **空き容量計算**: `content_offset - (96 + item_count * 4)`
- **境界検査**: `new_slots_end > new_content_offset` の場合は `DbError.Limit` で挿入を拒否する。

---

## 3. WAL レコード構造

WAL レコードはヘッダ (96B) と種別ごとのペイロードで構成される。

- **レコード種別 (`kind`)**:
  - `1`: Begin（トランザクション開始）
  - `2`: Redo（ページ全更新イメージ: 8192B ページをそのまま格納）
  - `3`: Commit（コミット記録）
  - `4`: Abort（ロールバック記録）
  - `5`: Checkpoint（チェックポイント記録）

---

## 4. 値・キー・行の符号化形式

### 4.1 値の型タグと表現
- `1`: `Int` (64bit LE 符号付き整数, 8 バイト)
- `2`: `Bool` (0 = false, 1 = true, 1 バイト)
- `3`: `Str` (u32 LE 長さ + UTF-8 バイト列)
- `4`: `Bytes` (u32 LE 長さ + バイト列)

### 4.2 大小順序規則 (ADR 0045)
- 異なる型同士の順序: `Int` < `Bool` < `Str` < `Bytes`
- 同一型同士の順序:
  - `Int`: 数値の昇順比較
  - `Bool`: false (0) < true (1)
  - `Str`: バイト列の辞書順比較
  - `Bytes`: バイト列の辞書順比較

### 4.3 キーおよび行の符号化
- **Key**: 値の列を順次符号化。最大符号化サイズは 1024 バイト (`max_key_encoded_size`)。
- **Row**: `u16 LE` 列数（最大 64） + 各列の値符号化列。最大符号化サイズは 4096 バイト (`max_row_encoded_size`)。

## 5. システム上限値一覧 (ADR 0045 決定 2)

| 項目 | 上限値 | 超過時の扱い |
|---|---|---|
| 最大ページ番号 | `16,777,216` (2^24 ページ = 128 GiB) | `DbError.Limit` で拒否 |
| テーブル数 / 索引数 | 各 `1,024` | `DbError.Limit` で拒否 |
| 列数 | `64` 列 | `DbError.Limit` で拒否 |
| 1 行最大サイズ | `4,096` バイト | `DbError.Limit` で拒否 |
| 1 キー最大サイズ | `1,024` バイト | `DbError.Limit` で拒否 |
| トランザクション更新ページ数 | `4,096` ページ (32 MiB) | `DbError.Limit` で拒否 |
| 1 トランザクション WAL 容量 | `67,108,864` バイト (64 MiB) | `DbError.Limit` で拒否 |
| WAL 総容量 | `67,108,864` バイト (64 MiB) | `DbError.Limit` で拒否 |
| 作業用メモリ上限 | `268,435,456` バイト (256 MiB) | `DbError.Limit` で拒否 |
| ページサイズ | `8,192` バイト固定 | 違反時は `DbError.Corrupt` |
| ヘッダサイズ | `96` バイト固定 | 違反時は `DbError.Corrupt` |
